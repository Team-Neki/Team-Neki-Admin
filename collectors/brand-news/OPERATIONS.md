# 자동 운영 판정

현재 6개 브랜드에서 실제 게시물을 추출했다. 예약 실행은 가능하도록 CLI·영속 상태·종료 코드를 갖췄지만 장기간 무인 수집은 검증하지 않았다. 매번 사람이 수집을 지시할 필요가 없는 구조와 항상 빠짐없이 수집되는 구조는 다르다.

## 경로별 판정

| 브랜드 | 경로 | 자동 운영의 남은 위험 |
| --- | --- | --- |
| 포토시그니처 | 공식 공개 HTML | 목록/선택자 변경, 첫 목록 12개 밖의 누락 |
| 하루필름 | 공식 공개 HTML | 목록/선택자 변경, 첫 목록 100개 밖의 누락 |
| 포토이즘 | 공개 Instagram 브라우저 | 로그인 요구·429·구조 변경, 최대 12개와 공동 게시물 누락 |
| 포토그레이 | 공개 Instagram 브라우저 | 위와 같음. 실제 상세 글 3개 실패 이력 있음 |
| 인생네컷 | 공개 Instagram 브라우저 | 위와 같음. 좋아요 접두어 없는 메타데이터 형식 보완 |
| 돈룩업 | 공개 Instagram 브라우저 | 위와 같음. 다른 계정 명의 공동 게시물 제외 |

공개 브라우저 경로는 조건부다. 로그인이나 인증을 우회하지 않는다. 제한이 계속되면 자동으로 성공하지 않으며 실패 상태와 오래된 저장본을 유지한다.

## 구현된 대응

- 요청 제한·401/403·로그인/인증 URL이면 해당 출처를 중단한다. 오류 200 페이지는 URL로 확인되지 않으면 메타데이터 오류로 잡힐 수 있다. Instagram 메타데이터 실패 3회 연속이면 추가 상세 이동을 중단한다.
- Instagram 최대 12개 상세, 이동 간격 2초, 후속 작업 제한용 120초 예산. 브라우저 실행·종료 자체의 강제 종료를 보장하지 않으므로 실행기에도 프로세스 제한 시간이 필요하다.
- 재시도 기본 대기: 429는 6시간, 로그인/인증/접근 거부는 12시간, 구조 변경은 1시간, 기타 부분 실패는 30분, 일반 오류는 15분. 연속 실패마다 2배, 자체 대기는 최대 24시간. 서버 Retry-After가 더 길면 우선한다. `--force`도 이 대기는 무시하지 않는다.
- 일부 성공을 전체 성공으로 처리하지 않는다. `partial`과 상세 실패 수를 저장하고 읽은 글은 반영하되 마지막 전체 성공 시각은 유지한다. 과거 `ok` 기록에 상세 실패가 있으면 실패로 판정한다.
- 같은 상태 경로에 대한 동시 실행 잠금과 임시 파일 교체 방식으로 저장한다. 실패·부분 실패·재시도 대기는 CLI 종료 코드 1, 정상/캐시는 0이다. 산출물 `run.json`과 `quality.json`으로 상태를 확인할 수 있다.
- Instagram 이미지 서명만 갱신되면 URL만 교체한다. 경로/본문 변경은 재검토한다. 만료 이미지에는 보고서의 원문 링크를 남긴다. 이것은 이미지 보관 대책이 아니다.

## 검증 범위

실제 접근에서 Instagram 이미지 6개의 서명 URL 만료, 포토그레이 상세 3개 실패, 인생네컷 메타데이터 차이를 확인했다. 실제 차단을 유발하기 위한 요청 폭주는 하지 않았다.

2026-10-10 보강 후 포토그레이 단독 재조회는 선택 12개·시도 12개·정상 추출 11개·실패 1개였다. `partial/layout-changed`와 1시간 재시도 대기가 실제 상태 파일에 저장됐고 누적 게시물은 193건에서 196건으로 늘었다. 이 실행은 전체 성공이 아니다.

`test/unattended-collection.test.mjs`는 가짜 브라우저로 429·로그인 전환·접근 거부·인증 화면·메타데이터 변경·예산 소진을 주입한다. 중단 시점, 부분 성공 보존, 브라우저 종료, 실패 대기 증가, 성공 후 초기화, 서명 변경 시 재검토 미발생을 검증한다. `collector.test.mjs`는 별도 실행에서 상태를 다시 읽었을 때 대기가 유지되고 기존 글을 보존하는지 검증한다. 이 테스트가 실제 Instagram의 장기 성공률을 증명하지는 않는다.

## 실제 운영 전에 연결할 것

GitHub Actions 6시간 간격 실행, 데이터 브랜치 영속화, 어드민 읽기 API/조회 탭은 코드로 구성했다. PR 머지 및 첫 실행이 아직 남아 있으므로 아래의 장기 검증/운영 알림 항목까지 완료됐다는 뜻은 아니다. 상세 절차는 [공유 수집 운영 문서](../../docs/operations/brand-news-collection.md)를 따른다.

1. Node.js 22.13+·Chrome이 있는 영속 실행기. 항상 같은 절대 상태 경로와 출력 경로를 넘긴다. 재시작 후 데이터가 사라지는 임시 경로는 피한다.
2. 실행 일정, 프로세스 제한 시간, 종료 코드와 오류 유형을 받는 알림. 자동 알림 전송과 예약 실행은 아직 설정하지 않았다. 동일 오류 반복은 묶고 정상 복구를 구분해야 한다.
3. 상태/산출물 백업과 실패한 잠금 파일 복구 절차. 기존 PID가 살아 있으면 잠금을 제거하지 않는다. 다중 실행기는 분산 잠금/저장소 없이는 사용하지 않는다.
4. 연속 운영 기간의 브랜드별 성공률, 마지막 전체 성공 시각, 목록 누락 비교. 마지막 성공이 오래되면 저장 건수가 있어도 최신으로 표시하지 않는다.
5. 목록 밖으로 밀린 글·공동 게시물의 보완, 알려진 게시물 재조회, 이미지 갱신/허가된 보관. 현재 최대 12개 조회로 과거 이미지 전체를 갱신할 수 없다.
6. 정규화 후보 검토와 어드민 연동. 기간·부스·촬영 가능 상태가 미확인인 후보를 자동 확정하지 않는다.

## 공식 API 대안

[Meta 공식 Instagram API with Facebook Login](https://www.postman.com/meta/instagram/folder/u4g5a2a/instagram-api-with-facebook-login)은 다른 비즈니스·크리에이터 계정의 공개 정보 조회 경로를 제공한다. 연결된 프로페셔널 계정과 권한이 필요하며 일반 개인 계정에는 적용되지 않는다. 실제 대상 4개 계정이 API로 조회되는지, 토큰/권한을 확보할 수 있는지는 검증하지 않았다. 브라우저 수집이 막혔을 때 자동으로 API로 전환하는 기능도 없다.

공유 Sites에는 정적 HTML만 배포한다. 링크 열기나 보고서 배포가 수집 예약을 만드는 것은 아니다.

## 이번 보강

- 문서 이동뿐 아니라 1차 Instagram XHR/fetch의 429도 관측한다. 차단 신호와 대기·이동·메타데이터 읽기를 경쟁시켜 추가 이동을 멈춘다.
- 실패 게시물 URL·실패 단계·횟수·다음 시각을 상태 파일에 저장한다. 신규 우선, 실패 큐 재시도, 기존 글 24시간 갱신 순이며 3회 실패하면 수동 검토가 필요하다. 출처 접근 제한은 게시물별 대기보다 우선한다.
- 과거 포토그레이 실패에는 URL 기록이 없어서 소급 식별하지 않는다. 다음 실제 시도부터 개별 기록을 남긴다. 초기 196건은 그대로 사용하되 부분 실패 상태도 유지한다.
- 전체 앱 `npm run check`, 수집기 테스트, Ant Design lint와 로컬 196건 렌더링을 검증한다. GitHub runner의 익명 Instagram 접근과 연속 운영 안정성은 머지 후 검증 대상이다.
