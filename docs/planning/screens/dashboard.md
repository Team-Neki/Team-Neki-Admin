# 대시보드 화면 기획서

## 기능 개요

운영자가 서비스의 활동 사용자와 누적 사용자 변화를 한 화면에서 확인하는 기능이다. 날짜를 쉽게 이동하며 DAU, WAU, MAU와 플랫폼별 누적 사용자 추이를 확인할 수 있게 한다.

- 진입 메뉴: 대시보드
- 관련 화면: 활동 사용자 현황, 활동 사용자 추이, 누적 사용자 추이
- 1차 범위: 목 데이터 기반 DAU·WAU·MAU 조회, 기본 범위 선택과 오늘·이번 주·이번 달 빠른 기간 프리셋, 전체·Android·iOS 누적 사용자 조회

대시보드에는 `바로 시작할 작업` 섹션을 제공하지 않는다. 실제 API의 주소, 필드명, enum과 집계 정책은 서버 스펙이 확정된 뒤 화면 모델과 분리된 adapter에서 결정한다.

## 기능에 필요한 정보

- 기준 기간에 해당하는 DAU, WAU와 MAU를 조회할 수 있어야 한다.
- 각 지표가 집계된 정확한 시작일과 종료일을 확인할 수 있어야 한다.
- 선택한 기간의 활동 사용자 추이를 조회할 수 있어야 한다.
- 선택한 날짜까지의 전체 누적 사용자 수를 확인할 수 있어야 한다.
- 날짜별 전체, Android와 iOS 누적 사용자 추이를 조회할 수 있어야 한다.
- 데이터의 마지막 갱신 시점을 확인할 수 있어야 한다.
- 실제 데이터 형식, 값 이름과 집계 기준은 백엔드 API 및 분석 정책에 맞춰 결정한다.

## 1. 기준 기간 선택

### 화면 설명

하나의 기준 기간 선택 영역에서 날짜를 일 단위로 고르고 오늘·이번 주·이번 달 빠른 기간 필터를 전환하는 기능이다. 조회 조건을 여러 곳에 나누지 않고 한 영역에서 조작할 수 있게 한다.

### 화면 구성

- 시작일·종료일 범위 선택기
- `오늘`, `이번 주`, `이번 달` 빠른 기간 프리셋
- 이전 기간과 다음 기간 이동
- `오늘`, `이번 주`, `이번 달` 빠른 이동
- 현재 선택한 실제 기간 표시

### 기간 필터와 기준 날짜

- 기준 날짜 선택기는 항상 날짜 단위로 표시한다.
- `오늘`은 기준 날짜를 오늘로 고정하고 하루를 조회한다.
- `이번 주`는 기준 날짜가 포함된 주를 조회한다.
- `이번 달`은 기준 날짜가 포함된 달을 조회한다.
- 범위 선택기는 시작일과 종료일 사이의 일별 데이터를 조회한다.
- 필터를 변경하면 기준 날짜를 오늘로 이동하고 같은 기준으로 지표를 갱신한다.

### 이전·다음 기간 이동

- 이전을 선택하면 현재 필터(오늘·이번 주·이번 달)만큼 한 기간 전으로 이동한다.
- 다음을 선택하면 현재 필터만큼 한 기간 뒤로 이동한다.
- 미래 기간은 선택할 수 없으며, 현재 기간에서는 다음 이동을 사용할 수 없게 한다.
- 이동이 완료되면 활동 사용자와 누적 사용자 영역을 같은 기준으로 함께 갱신한다.

### 빠른 이동

- `오늘`을 선택하면 오늘을 조회한다.
- `이번 주`를 선택하면 현재 주를 조회한다.
- `이번 달`을 선택하면 현재 달을 조회한다.
- 현재 선택된 빠른 이동 항목은 다른 항목과 구분해 표시한다.
- 빠른 이동은 캘린더를 여러 번 넘기지 않고 현재 기간으로 돌아오기 위한 보조 동작으로 제공한다.

### 진행 중인 기간

- 오늘, 이번 주와 이번 달처럼 아직 끝나지 않은 기간은 `집계 중`임을 표시한다.
- 진행 중인 기간의 값은 마지막으로 집계된 시점까지의 결과일 수 있으므로 마지막 갱신 시각을 함께 확인할 수 있게 한다.

## 2. 활동 사용자 현황

### 화면 설명

선택한 기준 기간과 연결되는 DAU, WAU와 MAU를 한눈에 비교하는 영역이다. 세 지표는 컴팩트한 요약 카드로 나란히 표시한다.

### 지표 표시 정보

| 지표 | 화면에서의 의미 |
| --- | --- |
| DAU | 기준일 하루 동안 유효 활동을 한 순 사용자 수 |
| WAU | 기준일을 포함한 최근 7일 동안 유효 활동을 한 순 사용자 수 |
| MAU | 기준일을 포함한 최근 30일 동안 유효 활동을 한 순 사용자 수 |

### 표시 원칙

- DAU, WAU와 MAU를 항상 함께 표시한다.
- 각 카드에는 사용자 수와 해당 값이 집계된 실제 기간을 함께 표시한다.
- 숫자는 천 단위 구분을 적용해 읽기 쉽게 표시한다.
- 값이 없거나 아직 집계되지 않은 경우 `0`으로 단정하지 않고 `—`로 표시한다.
- 카드 전체를 다른 화면으로 이동하는 버튼처럼 표현하지 않는다.
- 선택한 기간 필터에 대응하는 지표를 시각적으로 강조할 수 있다.

### 활동 사용자 추이

- DAU, WAU, MAU 추이 그래프를 항상 함께 표시한다.
- 각 그래프는 선택한 범위에 해당하는 동일한 조회 조건을 사용한다.
- 범위가 길어질수록 WAU와 MAU는 각 지표의 집계 간격에 맞춰 표시한다.
- 각 지점에는 실제 기간과 사용자 수를 확인할 수 있는 정보를 제공한다.
- DAU 값의 합으로 WAU나 MAU를 계산하지 않는다. 같은 사용자가 여러 날 활동할 수 있으므로 각 기간의 순 사용자를 별도로 집계한다.
- 기간 필터를 바꿀 때 화면 전체를 다시 불러오지 않고 지표 영역의 조회 상태를 갱신한다.

## 3. 총 사용자와 플랫폼별 누적 사용자

### 화면 설명

선택한 기준 기간의 종료일까지 가입한 총 사용자와 플랫폼별 누적 변화를 확인하는 영역이다.

### 화면 구성

- 선택한 날짜 기준 총 사용자 수
- 전체 누적 사용자 추이
- Android 누적 사용자 추이
- iOS 누적 사용자 추이
- 전체, Android와 iOS 표시 선택

### 누적 사용자 표시

- 총 사용자는 선택한 기준 기간의 종료일까지 포함한 누적 순 사용자 수로 표시한다.
- 기간 필터를 바꾸면 해당 기간의 날짜 간격으로 누적 추이를 표시한다.
- 각 지점에서 기준 날짜와 누적 사용자 수를 확인할 수 있게 한다.
- 전체, Android와 iOS를 구분해 같은 날짜 축에서 비교할 수 있게 한다.
- 표시 선택은 컴팩트한 체크박스 또는 범례 형태로 제공한다.
- 모든 항목을 숨겨 빈 차트가 되지 않도록 최소 하나의 항목은 표시된 상태로 유지한다.

### 플랫폼 수치 해석

- 전체 누적 사용자는 사용자 계정을 기준으로 중복을 제거한 값으로 다룬다.
- Android와 iOS를 모두 사용한 사용자의 분류 방식이 확정되기 전에는 두 플랫폼의 값을 더해 전체 사용자 수를 계산하지 않는다.
- 플랫폼을 확인할 수 없는 사용자가 생길 수 있으므로 전체 값과 플랫폼별 값의 합이 다를 수 있다.
- 화면에서는 adapter가 전달한 전체와 플랫폼별 값을 각각 표시하고 임의로 합산하거나 보정하지 않는다.

## 4. 화면 상태

### 조회 중

- 최초 진입 시 요약 카드와 추이 영역의 위치를 유지하는 로딩 상태를 표시한다.
- 기준 기간을 변경할 때는 지표 영역의 위치를 유지하고 갱신 중임을 표시한다.
- 여러 기준 기간을 빠르게 선택하면 마지막으로 선택한 기간의 결과만 화면에 반영한다.

### 데이터 없음

- 선택한 기간에 지표 데이터가 없으면 해당 값을 `—`로 표시한다.
- 전체 영역을 빈 화면으로 대체하지 않고 데이터가 없는 지표 또는 추이만 구분해 안내한다.
- 다른 날짜를 선택할 수 있는 기준 기간 선택 영역은 그대로 유지한다.

### 조회 실패

- 최초 조회에 실패하면 대시보드 데이터를 불러오지 못했다는 안내와 다시 불러오기 동작을 제공한다.
- 기간 변경 조회에 실패하면 선택한 조회 조건은 유지하고 지표 영역에 실패 안내와 재시도 동작을 표시한다.
- 일부 지표만 조회하지 못한 경우 전체 화면을 실패 상태로 바꾸지 않고 해당 영역만 구분한다.

### 조회 성공

- 선택한 기준 기간의 모든 지표와 추이를 같은 조회 기준으로 표시한다.
- 마지막 갱신 시각을 확인할 수 있게 한다.

## 5. 반응형 구성

- 넓은 화면에서는 DAU, WAU와 MAU 카드를 한 줄에 표시한다.
- 화면이 좁아지면 카드와 기간 선택 동작을 읽는 순서대로 줄바꿈한다.
- 작은 화면에서는 기간 필터, 기준 날짜 선택기와 이전·다음 동작을 두 줄 이상으로 나눌 수 있다.
- 기간 선택기 팝업은 현재 화면 너비 안에서 열려야 한다.
- 누적 사용자 범례는 축약하거나 줄바꿈하되 전체, Android와 iOS의 구분을 유지한다.
- 모든 화면 크기에서 문서 전체의 가로 넘침 없이 날짜 선택과 지표 확인을 완료할 수 있어야 한다.

## 6. 프로토타입 데이터와 API 연동 경계

### 현재 프로토타입

- 최근 여러 달의 변화와 날짜 이동을 확인할 수 있는 시드 목 데이터를 제공한다.
- DAU, WAU와 MAU는 각 기간의 순 사용자 지표를 별도로 제공한다.
- 전체, Android와 iOS 누적 사용자는 날짜별 목 시계열로 제공한다.
- 기준 기간 변경, 조회 중, 데이터 없음과 조회 실패를 메모리 기반 비동기 adapter로 재현한다.
- 화면은 목 데이터 파일을 직접 사용하지 않고 공통 관리자 adapter의 대시보드 조회 계약을 통해서만 데이터를 받는다.
- 외부 API를 호출하지 않으며 새로고침하면 초기 목 데이터 상태로 돌아간다.

### 실제 API 연결 시 필요한 동작

- 화면이 선택한 기간 필터와 기준 날짜를 adapter에 전달한다.
- adapter는 서버의 응답을 기간 라벨, DAU·WAU·MAU, 활동 사용자 추이, 총 사용자와 플랫폼별 누적 추이라는 화면 모델로 변환한다.
- 서버의 필드명, enum, 날짜 표현과 오류 형식은 API adapter 안에서만 화면 모델에 맞게 변환한다.
- 화면 컴포넌트는 API 주소나 서버 응답 구조를 직접 참조하지 않는다.
- 대시보드 데이터는 날짜 변경마다 독립적으로 조회할 수 있도록 기존 운영 데이터 전체 조회와 분리된 adapter 계약으로 제공한다.
- 같은 주·달 안에서 날짜를 바꿀 때는 기간 시작일을 조회 키로 사용해 중복 요청을 만들지 않는다.
- 선택한 기간의 추이 지표만 전체 시계열로 조회하고 나머지 DAU·WAU·MAU는 기준일 값만 조회한다.
- Amplitude 원본 응답은 60초 동안 서버에서 재사용하고, 외부 요청은 한 번에 하나씩 처리한다.

## 7. 추가로 확정할 집계 정책

다음 항목은 프로토타입 화면에서 임의의 서버 필드나 상태 값으로 확정하지 않고 실제 분석 정책과 API 스펙을 정할 때 합의한다.

- 날짜 경계와 화면 표시에 한국 표준시(KST)를 사용할지 여부
- 로그인, 앱 실행, 사진 저장 등 어떤 행동을 `활성 사용자`로 판단할지
- 한 주의 시작 요일과 진행 중인 주의 집계 범위
- 탈퇴, 휴면과 차단 사용자를 과거 및 현재 지표에 포함할지
- 한 사용자가 Android와 iOS를 모두 사용한 경우 플랫폼별 사용자로 분류하는 방식
- 플랫폼을 확인할 수 없는 사용자를 별도 분류할지
- 분석 데이터의 갱신 주기와 지연 허용 범위

프로토타입에서 날짜를 표시할 때는 일관된 목 데이터 확인을 위해 KST 기준 화면을 사용할 수 있지만, 이는 실제 API의 집계 기준을 확정하는 의미가 아니다.

## 8. 완료 기준

- 대시보드에 `바로 시작할 작업` 섹션이 표시되지 않는다.
- DAU, WAU와 MAU의 값과 각 지표의 실제 기준 기간을 확인할 수 있다.
- 기준 날짜를 일 단위로 선택하고 오늘·이번 주·이번 달 또는 직접 설정 범위를 바꿀 수 있다.
- 이전·다음 기간 이동과 오늘·이번 주·이번 달 빠른 이동을 사용할 수 있다.
- 선택한 날짜 기준 총 사용자와 전체·Android·iOS 누적 추이를 확인할 수 있다.
- 기준 기간을 변경하면 모든 지표와 추이가 같은 기준으로 갱신된다.
- 조회 중, 데이터 없음, 조회 실패와 부분 데이터 상태가 구분된다.
- 데스크톱, 태블릿과 모바일에서 가로 넘침 없이 기간 선택과 지표 확인이 가능하다.
- 화면 코드와 기획 문서에서 실제 API 필드명이나 내부 enum을 먼저 확정하지 않는다.
- 실제 API 연결 시 화면을 바꾸지 않고 adapter 구현체를 교체할 수 있다.
