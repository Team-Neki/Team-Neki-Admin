# 수동 알림 발송 화면 기획서

## 문서 정보

| 항목 | 내용 |
| --- | --- |
| 기능 ID | `MANUAL_NOTIFICATION` |
| 기능명 | 수동 알림 발송 |
| 원문 | [네키 어드민 기능 목록](https://sprint.suitestudy.com:4641/wiki/cmsa129da000hkb01b6bn2siv) |
| 진입 메뉴 | 운영 > 수동 알림 |
| 화면 | 알림 발송, 발송 이력, 발송 상세 |

## 1. 기능 개요

운영자가 사용자에게 전달할 푸시 알림을 직접 작성하고 발송하는 기능이다. 운영자는 발송 대상을 선택한 뒤 알림을 즉시 보내거나 원하는 시점으로 예약할 수 있다. 발송하거나 예약한 알림은 이력에서 확인하며, 아직 발송되지 않은 예약은 취소할 수 있다.

## 2. 기능이 의존하는 정보

수동 알림 기능이 동작하려면 다음 정보와 시스템 기능을 조회하거나 사용할 수 있어야 한다.

| 의존 항목 | 필요한 이유 |
| --- | --- |
| 사용자 식별 정보 | 알림 발송 대상을 구분한다. |
| 마케팅 수신 동의 정보 | 마케팅 수신에 동의한 사용자만 대상으로 선정한다. |
| 사용자 기기 운영체제 | Android 또는 iOS 사용자를 구분한다. |
| 푸시 알림 수신 가능 여부 | 실제로 푸시를 받을 수 있는 사용자를 구분한다. |
| 푸시 발송 토큰 | 사용자 기기로 알림을 전달한다. |
| 푸시 발송 기능 | 선택한 대상에게 알림 발송을 요청한다. |
| 예약 실행 기능 | 지정한 일시에 예약 알림을 발송한다. |
| 발송 이력 저장소 | 발송 요청, 예약, 취소, 처리 결과를 기록한다. |

| `TARGET_ANDROID` | Android 사용자 | 기기 운영체제, 푸시 수신 가능 여부, 푸시 발송 토큰 | Android 기기에서 푸시를 받을 수 있는 사용자 |
| `TARGET_IOS` | iOS 사용자 | 기기 운영체제, 푸시 수신 가능 여부, 푸시 발송 토큰 | iOS 기기에서 푸시를 받을 수 있는 사용자 |

## 7. MN-01 알림 발송

### 화면 설명

운영자가 사용자에게 보낼 알림을 작성하고 발송 대상과 발송 방식을 선택하는 화면이다.

### 화면 구성

| 영역 | 화면 요소 |
| --- | --- |
| 알림 작성 | 알림 제목 입력, 알림 내용 입력 |
| 발송 대상 | 전체 사용자, 마케팅 수신 동의 사용자, Android 사용자, iOS 사용자 선택 |
| 발송 방식 | 즉시 발송, 예약 발송 선택 |
| 예약 정보 | 예약 일시 입력 |
| 실행 | 즉시 발송 또는 발송 예약 버튼 |

### 기능별 정의

#### MN-01-F01 알림 제목과 내용 입력

- 설명: 사용자에게 전달할 푸시 알림의 제목과 본문을 작성한다.
- 트리거: 운영자가 알림 발송 화면의 제목 또는 내용 입력 영역을 선택한다.
- 사전 조건: 운영자가 알림 발송 화면에 진입해 있어야 한다.
- 필요한 데이터: 알림 제목, 알림 내용
- 처리: 입력한 제목과 내용을 현재 작성 중인 알림 정보에 반영한다.
- 처리 결과: 제목과 내용이 발송에 사용할 메시지로 준비된다.

#### MN-01-F02 전체 사용자 대상 선택

- 설명: 현재 푸시 알림을 받을 수 있는 전체 사용자를 발송 대상으로 선택한다.
- 트리거: 운영자가 발송 대상에서 `전체 사용자`를 선택한다.
- 사전 조건: 사용자별 푸시 수신 가능 여부와 푸시 발송 토큰을 조회할 수 있어야 한다.
- 필요한 데이터: 사용자 ID, 푸시 수신 가능 여부, 푸시 발송 토큰
- 처리: 푸시 수신이 가능한 전체 사용자를 발송 대상 조건으로 설정한다.
- 처리 결과: 발송 대상 유형이 `TARGET_ALL`로 설정된다.

#### MN-01-F03 마케팅 수신 동의 사용자 대상 선택

- 설명: 마케팅 알림 수신에 동의한 사용자만 발송 대상으로 선택한다.
- 트리거: 운영자가 발송 대상에서 `마케팅 수신 동의 사용자`를 선택한다.
- 사전 조건: 사용자별 마케팅 수신 동의 여부와 푸시 수신 가능 여부를 조회할 수 있어야 한다.
- 필요한 데이터: 사용자 ID, 마케팅 수신 동의 여부, 푸시 수신 가능 여부, 푸시 발송 토큰
- 처리: 마케팅 수신에 동의했고 푸시를 받을 수 있는 사용자를 발송 대상 조건으로 설정한다.
- 처리 결과: 발송 대상 유형이 `TARGET_MARKETING`으로 설정된다.

#### MN-01-F04 Android 사용자 대상 선택

- 설명: Android 기기로 푸시를 받을 수 있는 사용자를 발송 대상으로 선택한다.
- 트리거: 운영자가 발송 대상에서 `Android 사용자`를 선택한다.
- 사전 조건: 사용자 기기의 운영체제와 푸시 수신 가능 여부를 조회할 수 있어야 한다.
- 필요한 데이터: 사용자 ID, 기기 운영체제, 푸시 수신 가능 여부, 푸시 발송 토큰
- 처리: Android 기기를 사용하며 푸시를 받을 수 있는 사용자를 발송 대상 조건으로 설정한다.
- 처리 결과: 발송 대상 유형이 `TARGET_ANDROID`로 설정된다.

#### MN-01-F05 iOS 사용자 대상 선택

- 설명: iOS 기기로 푸시를 받을 수 있는 사용자를 발송 대상으로 선택한다.
- 트리거: 운영자가 발송 대상에서 `iOS 사용자`를 선택한다.
- 사전 조건: 사용자 기기의 운영체제와 푸시 수신 가능 여부를 조회할 수 있어야 한다.
- 필요한 데이터: 사용자 ID, 기기 운영체제, 푸시 수신 가능 여부, 푸시 발송 토큰
- 처리: iOS 기기를 사용하며 푸시를 받을 수 있는 사용자를 발송 대상 조건으로 설정한다.
- 처리 결과: 발송 대상 유형이 `TARGET_IOS`로 설정된다.

#### MN-01-F06 즉시 발송

- 설명: 작성한 알림을 선택한 대상에게 바로 발송한다.
- 트리거: 운영자가 발송 방식으로 `즉시 발송`을 선택하고 실행 버튼을 누른다.
- 사전 조건: 알림 제목, 알림 내용, 발송 대상 유형이 설정돼 있고 푸시 발송 기능을 사용할 수 있어야 한다.
- 필요한 데이터: 알림 제목, 알림 내용, 발송 대상 유형, 대상 사용자의 푸시 발송 토큰
- 처리: 대상 조건에 맞는 사용자를 조회하고 푸시 발송을 요청한 뒤 발송 이력을 생성한다.
- 처리 결과: 알림 상태가 `SENT`로 기록되고 발송 이력에서 확인할 수 있다.

#### MN-01-F07 예약 발송

- 설명: 작성한 알림이 지정한 날짜와 시간에 발송되도록 예약한다.
- 트리거: 운영자가 발송 방식으로 `예약 발송`을 선택하고 예약 일시를 입력한 뒤 실행 버튼을 누른다.
- 사전 조건: 알림 제목, 알림 내용, 발송 대상 유형, 예약 일시가 설정돼 있고 예약 실행 기능을 사용할 수 있어야 한다.
- 필요한 데이터: 알림 제목, 알림 내용, 발송 대상 유형, 예약 일시
- 처리: 알림과 예약 정보를 저장하고 예약 실행 기능에 발송 작업을 등록한다.
- 처리 결과: 알림 상태가 `SCHEDULED`로 기록되고 발송 이력에서 확인할 수 있다.

### 기본 이용 흐름

1. 운영자가 `운영 > 수동 알림` 메뉴에서 알림 발송 화면에 진입한다.
2. 알림 제목과 내용을 입력한다.
3. 발송 대상 유형을 선택한다.
4. 즉시 발송 또는 예약 발송을 선택한다.
5. 예약 발송인 경우 예약 일시를 입력한다.
6. 실행 버튼을 눌러 발송하거나 예약한다.
7. 처리된 알림을 발송 이력에서 확인한다.

## 8. MN-02 발송 이력

### 화면 설명

즉시 발송했거나 예약한 알림과 취소된 예약 알림을 목록으로 확인하는 화면이다.

### 목록 표시 정보

| 항목 | 설명 |
| --- | --- |
| 알림 제목 | 발송하거나 예약한 알림의 제목 |
| 발송 대상 | 선택한 발송 대상 유형 |
| 발송 방식 | 즉시 발송 또는 예약 발송 |
| 발송 상태 | 예약, 발송 완료, 취소 상태 |
| 관련 일시 | 생성 일시, 예약 일시 또는 발송 일시 |
| 작업 | 상세 확인, 예약 취소 |

### 기능별 정의

#### MN-02-F01 발송 이력 조회

- 설명: 발송, 예약, 취소된 알림을 목록으로 확인한다.
- 트리거: 운영자가 발송 이력 화면에 진입한다.
- 사전 조건: 알림 발송 요청과 상태 변경 결과가 발송 이력 저장소에 기록돼 있어야 한다.
- 필요한 데이터: 알림 ID, 알림 제목, 발송 대상 유형, 발송 방식, 발송 상태, 생성 일시, 예약 일시, 발송 일시
- 처리: 저장된 알림 이력을 조회해 목록 항목으로 구성한다.
- 처리 결과: 발송 이력 목록이 화면에 표시된다.

#### MN-02-F02 발송 상세 진입

- 설명: 선택한 발송 이력의 메시지와 발송 정보를 확인하는 상세 화면을 연다.
- 트리거: 운영자가 발송 이력에서 특정 알림의 상세 보기를 선택한다.
- 사전 조건: 선택한 알림 ID에 해당하는 발송 이력이 존재해야 한다.
- 필요한 데이터: 알림 ID
- 처리: 선택한 알림 ID를 기준으로 상세 정보를 조회한다.
- 처리 결과: `MN-03 발송 상세`가 표시된다.

#### MN-02-F03 예약 발송 상태 확인

- 설명: 예약한 알림이 아직 대기 중인지 발송됐는지 또는 취소됐는지 확인한다.
- 트리거: 운영자가 발송 이력 목록을 확인한다.
- 사전 조건: 예약 알림의 현재 상태가 발송 이력에 반영돼 있어야 한다.
- 필요한 데이터: 알림 ID, 예약 일시, 발송 상태
- 처리: 예약 알림의 현재 발송 상태를 목록에 연결한다.
- 처리 결과: 예약 알림에 `SCHEDULED`, `SENT`, `CANCELLED` 중 현재 상태가 표시된다.

#### MN-02-F04 예약 발송 취소

- 설명: 아직 실행되지 않은 예약 발송을 취소한다.
- 트리거: 운영자가 `SCHEDULED` 상태의 알림에서 예약 취소를 선택한다.
- 사전 조건: 대상 알림이 `SCHEDULED` 상태이고 예약 실행 기능에서 해당 작업을 찾을 수 있어야 한다.
- 필요한 데이터: 알림 ID, 예약 일시, 발송 상태, 예약 작업 식별 정보
- 처리: 예약 실행 기능에 등록된 발송 작업을 중단하고 발송 이력의 상태를 변경한다.
- 처리 결과: 알림 상태가 `CANCELLED`로 변경되고 발송 이력에 반영된다.

## 10. 주요 시나리오

### MN-SC01 전체 사용자에게 즉시 발송

1. 운영자가 알림 제목과 내용을 입력한다.
2. 발송 대상으로 `전체 사용자`를 선택한다.
3. 발송 방식으로 `즉시 발송`을 선택한다.
4. 시스템이 푸시 수신이 가능한 전체 사용자를 발송 대상으로 조회한다.
5. 시스템이 푸시 발송을 요청하고 발송 이력을 생성한다.
6. 운영자가 발송 이력에서 `SENT` 상태를 확인한다.

### MN-SC02 마케팅 수신 동의 사용자에게 예약 발송

1. 운영자가 알림 제목과 내용을 입력한다.
2. 발송 대상으로 `마케팅 수신 동의 사용자`를 선택한다.
3. 발송 방식으로 `예약 발송`을 선택하고 예약 일시를 입력한다.
4. 시스템이 알림과 예약 정보를 저장하고 예약 작업을 등록한다.
5. 운영자가 발송 이력에서 `SCHEDULED` 상태를 확인한다.
6. 예약 일시가 되면 시스템이 마케팅 수신 동의 여부와 푸시 수신 가능 여부를 기준으로 대상을 조회해 발송한다.
7. 발송 후 알림 상태가 `SENT`로 변경된다.

### MN-SC03 예약 발송 취소

1. 운영자가 발송 이력에서 `SCHEDULED` 상태의 알림을 확인한다.
2. 운영자가 예약 취소를 선택한다.
3. 시스템이 등록된 예약 작업을 중단한다.
4. 알림 상태가 `CANCELLED`로 변경된다.
5. 운영자가 발송 이력에서 취소 상태를 확인한다.
