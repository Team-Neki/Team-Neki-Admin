# 수동 알림 발송 화면 기획서

## 기능 개요

운영자가 사용자에게 전달할 푸시 알림을 작성하고 즉시 또는 예약 발송하는 기능이다. 발송 전인 알림은 `예약 중`, 발송을 시도한 알림은 `발송 이력`에서 구분해 확인한다.

- 원문: [네키 어드민 기능 목록](https://sprint.suitestudy.com:4641/wiki/cmsa129da000hkb01b6bn2siv)
- 진입 메뉴: 운영 > 수동 알림
- 관련 화면: 알림 작성, 예약 중, 발송 이력, 알림 상세

## 알림 발송 화면

### 화면 구성

- 알림 제목 입력
- 알림 내용 입력
- 클릭 시 이동 위치 입력
- 발송 대상 선택
- 즉시 발송 또는 예약 발송 선택
- 발송 실행

## 알림 작성 정보

### 알림 제목과 내용

- 알림 제목은 필수로 입력한다.
- 알림 내용은 필수로 입력한다.
- 입력한 제목과 내용은 실제 푸시 알림에 표시된다.

### 클릭 시 이동 위치

- 사용자가 푸시 알림을 눌렀을 때 이동할 위치를 선택적으로 입력할 수 있다.
- 1차에서는 내부 화면과 외부 링크를 구분하지 않고 하나의 텍스트 필드로 제공한다.
- 이동 위치를 입력하지 않아도 알림을 발송할 수 있다.
- 이동 위치의 형식과 처리 방식은 이후 기능 고도화와 API 협의 과정에서 결정한다.

## 발송 대상 선택

### 기본 원칙

- 모든 수동 알림은 마케팅 수신에 동의한 사용자만 대상으로 한다.
- 마케팅 수신 동의 여부는 운영자가 화면에서 선택하지 않고 모든 발송에 기본 적용한다.
- 발송 대상은 라디오 버튼으로 한 가지 범위만 선택한다.
- 선택지는 `전체`, `Android`, `iOS`, `특정 사용자`로 제공한다.

### 전체

- 마케팅 수신에 동의했고 현재 푸시 알림을 받을 수 있는 전체 사용자를 의미한다.
- Android와 iOS를 모두 포함한다.

### Android 또는 iOS

- Android를 선택하면 마케팅 수신에 동의한 Android 사용자를 대상으로 한다.
- iOS를 선택하면 마케팅 수신에 동의한 iOS 사용자를 대상으로 한다.
- 두 플랫폼은 동시에 선택하지 않는다.

### 특정 사용자

- 닉네임으로 사용자를 검색해 한 명 이상 선택할 수 있다.
- 검색 결과에는 닉네임, 사용자 구분값, 사용 플랫폼을 표시한다.
- 현재 알림을 받을 수 없는 사용자는 결과에서 확인할 수 있지만 선택할 수 없다.
- 선택한 사용자는 검색어가 바뀌어도 유지되며 여러 명을 함께 발송 대상으로 지정할 수 있다.
- 사용자를 선택하지 않은 상태에서는 발송하거나 예약할 수 없다.

### 발송 대상 선택에 필요한 정보

- 사용자별 마케팅 수신 동의 여부를 확인할 수 있어야 한다.
- 사용자가 알림을 받을 기기의 종류를 확인할 수 있어야 한다.
- 현재 푸시 알림을 받을 수 있는 사용자인지 확인할 수 있어야 한다.
- 선택한 조건에 해당하는 예상 발송 인원을 조회할 수 있어야 한다.
- 특정 사용자 발송을 위해 닉네임 검색과 수신 가능 여부 확인이 가능해야 한다.
- 실제 데이터 형식과 값 이름은 백엔드 API 스펙에 맞춰 결정한다.

## 즉시 발송

### 기능 설명

운영자가 작성한 알림을 선택한 발송 대상에게 바로 보내는 기능이다. 발송 전 확인 팝업을 통해 알림 내용과 대상을 최종 확인한다.

### 사전 조건

- 알림 제목과 내용이 입력돼 있어야 한다.
- 발송 대상이 선택돼 있어야 한다.
- 선택한 조건에 해당하는 예상 발송 인원을 조회할 수 있어야 한다.
- 실제로 푸시 알림을 받을 수 있는 대상 사용자가 존재해야 한다.
- 클릭 시 이동 위치는 선택 정보이므로 입력하지 않아도 된다.

### 발송 전 확인 팝업

운영자가 `보내기`를 선택하면 바로 발송하지 않고 확인 팝업을 표시한다.

팝업에는 다음 내용을 표시한다.

- 알림 제목
- 알림 내용
- 클릭 시 이동 위치
- 선택한 발송 대상
- 예상 발송 인원

예상 발송 인원은 확인 팝업을 여는 시점에 조회한다.

팝업에는 다음 버튼을 제공한다.

- 취소
- 보내기

### 발송 처리

- 운영자가 확인 팝업에서 `보내기`를 선택하면 알림 발송을 시작한다.
- 발송 처리 중에는 실행 버튼을 다시 누를 수 없도록 한다.
- 같은 알림이 중복 발송되지 않도록 한 번의 발송 요청만 처리한다.

### 발송 성공

발송이 성공하면 완료 안내를 표시하고 다음 행동을 선택할 수 있게 한다.

- 새 알림 작성
- 발송 이력 보기

`새 알림 작성`을 선택하면 입력 내용을 초기화한 알림 발송 화면을 보여준다. `발송 이력 보기`를 선택하면 방금 발송한 알림을 확인할 수 있는 발송 이력 화면으로 이동한다.

### 발송 실패

- 발송이 실패하면 알림 발송 화면을 유지한다.
- 운영자가 입력한 제목, 내용, 이동 위치, 발송 대상은 그대로 유지한다.
- 발송에 실패했다는 안내를 표시한다.
- 실패 건의 저장과 재시도 정책은 백엔드 API 협의 과정에서 결정한다.

### Discord 웹훅 전송

알림 발송 요청이 정상 처리되면 운영 기록을 Discord 웹훅으로 함께 전송한다.

Discord 메시지에는 다음 내용을 포함한다.

- 알림 제목
- 알림 내용
- 클릭 시 이동 위치
- 발송 대상
- 예상 발송 인원
- 발송 시각
- 해당 알림의 발송 이력 링크

Discord 메시지에는 별도의 사용자 또는 역할 멘션을 포함하지 않는다.

Discord 웹훅 전송 결과는 알림 발송 상태에 영향을 주지 않는다. 웹훅 전송 성공 또는 실패 여부는 발송 이력 목록과 발송 상세에 표시하지 않는다.

Discord 연동을 위해 웹훅을 보낼 수 있는 연결 정보가 준비돼 있어야 한다. 실제 웹훅 주소, 메시지 형식과 전송 방식은 연동 단계에서 결정한다.

### 즉시 발송 기본 흐름

1. 운영자가 알림 제목과 내용을 입력한다.
2. 필요한 경우 클릭 시 이동 위치를 입력한다.
3. 발송 대상을 선택한다.
4. 운영자가 `보내기`를 선택한다.
5. 시스템이 예상 발송 인원을 조회하고 확인 팝업을 표시한다.
6. 운영자가 팝업의 내용을 확인하고 `보내기`를 누른다.
7. 알림 발송을 처리하고 발송 이력을 생성한다.
8. 발송 성공 기록을 Discord 웹훅으로 전송한다.
9. 운영자에게 발송 완료를 안내한다.
10. 운영자가 새 알림 작성 또는 발송 이력 보기를 선택한다.

## 예약 발송

### 기능 설명

운영자가 작성한 알림이 지정한 날짜와 시간에 발송되도록 예약하는 기능이다. 즉시 발송과 동일한 작성 화면에서 발송 방식만 예약 발송으로 변경해 사용한다.

### 예약 일시 입력

- 예약 발송을 선택하면 날짜와 시간을 한 번에 선택할 수 있는 입력 영역을 표시한다.
- 알림 제목, 내용, 클릭 시 이동 위치와 발송 대상은 즉시 발송과 동일한 항목을 사용한다.
- 클릭 시 이동 위치는 선택 정보이므로 입력하지 않아도 예약할 수 있다.

### 사전 조건

- 알림 제목과 내용이 입력돼 있어야 한다.
- 발송 대상이 선택돼 있어야 한다.
- 예약 날짜와 시간이 입력돼 있어야 한다.
- 선택한 조건에 해당하는 예상 발송 인원을 조회할 수 있어야 한다.
- 예약할 시점에 대상 사용자를 확인할 수 있어야 한다.

### 예약 전 확인 팝업

운영자가 `예약하기`를 선택하면 바로 예약하지 않고 확인 팝업을 표시한다.

팝업에는 다음 내용을 표시한다.

- 알림 제목
- 알림 내용
- 클릭 시 이동 위치
- 선택한 발송 대상
- 예상 발송 인원
- 예약 일시

예상 발송 인원은 확인 팝업을 여는 시점에 조회한다.

팝업에는 다음 버튼을 제공한다.

- 취소
- 예약하기

### 발송 대상 확정

- 예약 발송 대상은 예약을 등록하는 시점의 사용자 정보를 기준으로 확정한다.
- 예약 후 새로 조건을 만족한 사용자는 기존 예약 대상에 추가하지 않는다.
- 실제 발송 직전에는 마케팅 수신 동의가 철회됐거나 푸시를 받을 수 없게 된 사용자를 대상에서 제외한다.
- 예약 확인 팝업의 예상 인원과 실제 발송 인원은 사용자 상태 변경에 따라 달라질 수 있다.

### 예약 완료

예약이 완료되면 완료 안내를 표시하고 다음 행동을 선택할 수 있게 한다.

- 새 알림 작성
- 예약 중 보기

`새 알림 작성`을 선택하면 입력 내용을 초기화한 알림 작성 화면을 보여준다. `예약 중 보기`를 선택하면 방금 등록한 예약을 확인할 수 있는 목록으로 이동한다.

### 예약 실패

- 예약에 실패하면 알림 발송 화면을 유지한다.
- 운영자가 입력한 제목, 내용, 이동 위치, 발송 대상, 예약 일시는 그대로 유지한다.
- 예약에 실패했다는 안내를 표시한다.
- 실패 건의 저장과 재시도 정책은 백엔드 API 협의 과정에서 결정한다.

### 예약 알림의 Discord 웹훅 전송

- 예약을 등록하는 시점에는 Discord 웹훅을 보내지 않는다.
- 예약한 알림이 실제로 발송되고 발송 요청이 정상 처리된 시점에 Discord 웹훅을 전송한다.
- Discord 메시지 구성은 즉시 발송과 동일하게 알림 내용, 발송 정보와 발송 이력 링크를 포함한다.
- Discord 웹훅 전송 결과는 알림 발송 상태에 영향을 주지 않으며 발송 이력 목록과 발송 상세에 표시하지 않는다.

### 예약 발송 기본 흐름

1. 운영자가 알림 제목과 내용을 입력한다.
2. 필요한 경우 클릭 시 이동 위치를 입력한다.
3. 발송 대상을 선택한다.
4. 발송 방식으로 예약 발송을 선택한다.
5. 예약 날짜와 시간을 입력한다.
6. 시스템이 예상 발송 인원을 조회하고 확인 팝업을 표시한다.
7. 운영자가 팝업의 내용을 확인하고 `예약하기`를 누른다.
8. 시스템이 현재 조건에 맞는 대상 사용자를 확정하고 예약을 등록한다.
9. 운영자에게 예약 완료를 안내한다.
10. 운영자가 새 알림 작성 또는 예약 중 보기를 선택한다.
11. 예약 일시가 되면 마케팅 수신 동의와 푸시 수신 가능 여부를 다시 확인해 제외 대상만 제거한 뒤 알림을 발송한다.
12. 발송 성공 기록과 발송 이력 링크를 Discord 웹훅으로 전송한다.

## 예약 중

### 기능 설명

아직 발송되지 않은 `예약 대기` 알림만 모아 확인하는 목록이다.

### 목록 표시 정보

- 알림 제목과 클릭 시 이동 위치
- 발송 대상과 예상 발송 인원
- 예약 일시
- 상세 보기와 예약 취소

### 목록 동작

- 가까운 예약 일시부터 표시한다.
- 알림 제목으로 검색할 수 있다.
- 새 예약이 등록되면 목록과 탭 건수를 즉시 갱신한다.
- 예약을 취소하면 해당 알림은 목록에서 즉시 제외한다.
- 예약이 실행되면 `예약 중`에서 사라지고 처리 결과가 `발송 이력`에 표시된다.

## 예약 발송 취소

### 기능 설명

아직 발송되지 않은 예약 알림의 발송을 취소하는 기능이다. 발송 이력 목록과 발송 상세 팝업에서 모두 취소할 수 있다.

### 사전 조건

- 취소하려는 알림이 예약된 알림이어야 한다.
- 예약한 발송이 아직 실행되지 않은 상태여야 한다.
- 취소할 예약 알림의 제목, 발송 대상, 예상 발송 인원과 예약 일시를 확인할 수 있어야 한다.

### 취소 진입 위치

- `예약 중` 목록에서 예약 알림의 취소를 선택할 수 있다.
- 예약 상세 팝업에서도 예약 알림의 취소를 선택할 수 있다.
- 이미 발송됐거나 취소된 알림에는 취소 동작을 제공하지 않는다.

### 취소 확인 팝업

운영자가 예약 취소를 선택하면 바로 취소하지 않고 확인 팝업을 표시한다.

팝업에는 다음 내용을 표시한다.

- 알림 제목
- 발송 대상
- 예상 발송 인원
- 예약 일시

팝업에는 다음 버튼을 제공한다.

- 취소하지 않기
- 예약 취소

별도의 취소 사유는 입력받지 않는다.

### 취소 완료

- 예약 취소가 완료되면 `예약 중` 목록을 즉시 갱신한다.
- 취소한 알림은 `예약 중`과 `발송 이력`에 표시하지 않는다.
- 운영자에게 예약 취소가 완료됐다는 안내를 표시한다.
- 예약 취소 기록은 Discord 웹훅으로 전송하지 않는다.

### 취소 실패

- 취소에 실패하면 기존 예약 상태를 유지한다.
- 운영자에게 예약 취소에 실패했다는 안내를 표시한다.
- `예약 중` 목록과 상세 정보에는 변경 전 예약 상태를 그대로 표시한다.

### 예약 취소 기본 흐름

1. 운영자가 `예약 중` 목록 또는 예약 상세에서 예약 취소를 선택한다.
2. 시스템이 알림 제목, 발송 대상, 예상 발송 인원과 예약 일시를 포함한 확인 팝업을 표시한다.
3. 운영자가 팝업에서 `예약 취소`를 선택한다.
4. 예약 발송을 취소한다.
5. `예약 중` 목록을 갱신하고 취소 완료 안내를 표시한다.

## 발송 이력

### 기능 설명

실제로 발송 처리를 시도한 알림만 목록으로 확인하는 기능이다. 발송 완료와 발송 실패는 포함하고, 예약 대기와 취소는 포함하지 않는다.

### 목록 표시 정보

| 항목 | 설명 |
| --- | --- |
| 알림 제목 | 발송을 시도한 알림의 제목 |
| 클릭 시 이동 위치 | 알림 작성 시 선택적으로 입력한 이동 위치 |
| 발송 대상 | 전체, Android, iOS, 특정 사용자 중 선택한 대상 |
| 예상 발송 인원 | 발송 확인 시점에 조회한 대상 인원 |
| 실제 발송 인원 | 실제 발송 처리 대상이 된 인원 |
| 발송 방식 | 즉시 발송 또는 예약 발송 |
| 상태 | 발송 완료 또는 발송 실패 |
| 발송 일시 | 실제 발송을 처리한 일시 |
| 작업 | 상세 보기 |

### 목록 정렬

- 최근 생성한 알림부터 표시한다.
- 새로 발송한 알림을 목록 위쪽에서 바로 확인할 수 있어야 한다.

### 검색과 필터

- 알림 제목으로 이력을 검색할 수 있다.
- 즉시 발송과 예약 발송을 구분해 볼 수 있는 발송 방식 필터를 제공한다.
- 발송 완료와 발송 실패를 구분해 볼 수 있는 결과 필터를 제공한다.
- 검색과 필터를 함께 적용할 수 있다.

### 발송 인원 표시

- 예상 발송 인원과 실제 발송 인원을 함께 표시한다.
- 예약 이후 사용자 상태가 달라진 경우 예상 인원과 실제 발송 인원이 다를 수 있다.

### 실패한 발송 이력

- 발송에 실패한 알림도 발송 이력에 표시한다.
- 실패한 항목은 성공한 발송과 구분되는 상태로 표시한다.
- 실패 원인의 상세 정보와 재시도 방식은 백엔드 API 협의 과정에서 결정한다.

### 목록 동작

- 각 항목에서 발송 상세를 열 수 있다.

### 페이지 이동

- 발송 이력이 많아지면 페이지 번호 방식으로 목록을 나눠서 표시한다.
- 운영자는 이전 또는 다음 페이지와 원하는 페이지 번호를 선택할 수 있다.

### 화면 상태

#### 조회 중

- 발송 이력을 불러오는 동안 목록 영역에 로딩 상태를 표시한다.

#### 이력 없음

- 발송 이력이 없으면 아직 발송한 알림이 없다는 안내를 표시한다.
- 새 알림을 작성할 수 있는 이동 동작을 함께 제공한다.

#### 조회 실패

- 발송 이력 조회에 실패했다는 안내를 표시한다.
- 운영자가 목록을 다시 불러올 수 있는 동작을 제공한다.

### 발송 이력 기본 흐름

1. 운영자가 발송 이력 화면에 진입한다.
2. 최근 생성한 알림부터 목록에 표시한다.
3. 필요한 경우 제목을 검색하거나 발송 방식과 상태 필터를 적용한다.
4. 운영자가 목록에서 알림의 대상, 인원, 방식, 상태와 발송 일시를 확인한다.
5. 자세한 정보가 필요하면 상세 보기를 선택한다.

## 발송 상세

### 기능 설명

발송 이력 목록에서 선택한 알림의 전체 내용을 확인하는 기능이다. 별도 화면으로 이동하지 않고 화면 중앙의 상세 팝업으로 표시한다.

### 상세 팝업 표시 정보

- 알림 제목
- 알림 내용
- 클릭 시 이동 위치
- 발송 대상
- 예상 발송 인원
- 실제 발송 인원
- 발송 방식
- 현재 상태
- 예약 일시
- 발송 일시

Discord 웹훅 전송 결과는 상세 팝업에 표시하지 않는다.

### 알림 내용 표시

- 알림 제목과 내용은 운영자가 입력한 텍스트 형태로 표시한다.
- 실제 푸시 형태의 미리보기는 제공하지 않는다.

### 상세 팝업 동작

- 팝업을 닫고 발송 이력 목록으로 돌아갈 수 있다.

### 실패 정보

- 발송에 실패한 알림은 실패 상태를 표시한다.
- 확인할 수 있는 실패 사유가 있으면 상세 팝업에 함께 표시한다.
- 실패 사유의 데이터 형식은 백엔드 API 스펙에 맞춰 결정한다.

### Discord 발송 이력 링크

- Discord 메시지의 발송 이력 링크를 누르면 네키 어드민의 발송 이력 화면으로 이동한다.
- 발송 이력 화면이 열린 뒤 링크에 해당하는 알림의 상세 팝업을 자동으로 표시한다.
- Discord 링크를 통해 진입해도 목록에서 상세 보기를 선택한 경우와 동일한 정보를 보여준다.

### 발송 상세 기본 흐름

1. 운영자가 발송 이력 목록에서 상세 보기를 선택하거나 Discord의 발송 이력 링크를 누른다.
2. 시스템이 선택한 알림의 상세 정보를 불러온다.
3. 화면 중앙에 발송 상세 팝업을 표시한다.
4. 운영자가 알림 내용, 대상, 인원, 발송 방식, 상태와 발송 일시를 확인한다.
