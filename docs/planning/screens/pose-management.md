# 포즈 관리 화면 기획서

## 기능 개요

운영자가 촬영 포즈 이미지를 등록하고, 함께 찍는 인원수에 따라 포즈를 빠르게 찾아볼 수 있는 기능이다. 이미지 탐색이 핵심이므로 표보다 썸네일 카드 목록을 사용한다.

- 참고 화면: [Neki Admin 포즈 관리](https://yapp-admin.suitestudy.com/)
- 진입 메뉴: 운영 > 포즈 관리
- 관련 화면: 포즈 목록, 포즈 업로드 팝업, 이미지 크게 보기
- 1차 범위: 포즈 조회, 1~4인 필터, 이미지 다중 업로드

포즈 삭제, 순서 변경, 이름 수정과 공개 상태 관리는 이번 범위에 포함하지 않는다. 실제 API의 필드명, 상태 값과 업로드 방식은 서버 스펙이 확정된 뒤 화면 모델과 분리된 adapter에서 결정한다.

## 기능에 필요한 정보

- 등록된 포즈의 이미지를 조회할 수 있어야 한다.
- 각 포즈가 몇 명이 함께 찍는 포즈인지 확인할 수 있어야 한다.
- 포즈가 등록된 시점을 확인할 수 있어야 한다.
- 운영자가 선택한 원본 파일명을 업로드 과정과 목록에서 확인할 수 있어야 한다.
- 새 이미지를 업로드하고 등록 결과를 받을 수 있어야 한다.
- 실제 데이터 형식, 식별자와 인원수 값의 표현 방식은 백엔드 API 스펙에 맞춰 결정한다.

## 1. 포즈 목록

### 화면 설명

등록된 촬영 포즈를 이미지 카드로 조회하고 인원수별로 필터링하는 화면이다. 참고 화면의 이미지 중심 구성과 인원수 배지를 유지하면서, 전체와 인원수별 등록 건수를 한눈에 확인할 수 있는 필터 영역을 제공한다.

### 화면 구성

- 화면 제목과 설명
- 포즈 업로드 버튼
- 전체 포즈 수
- 전체, 1인, 2인, 3인, 4인 필터
- 포즈 이미지 카드 목록
- 이미지 크게 보기

### 포즈 카드 표시 정보

| 항목 | 설명 |
| --- | --- |
| 포즈 이미지 | 운영자가 등록한 촬영 포즈 이미지 |
| 인원수 | 해당 포즈를 함께 찍는 사람 수 |
| 등록 시각 | 포즈가 등록된 날짜와 시간 |
| 원본 파일명 | 업로드할 때 선택한 이미지의 파일명 |

카드의 이미지를 선택하면 원본 비율을 확인할 수 있는 크게 보기를 제공한다. 카드 전체에서 별도의 수정이나 삭제 동작은 제공하지 않는다.

### 목록 정렬

- 최근 등록한 포즈부터 표시한다.
- 새로 업로드한 포즈는 목록 가장 앞에서 바로 확인할 수 있어야 한다.
- 새 포즈를 등록한 직후에는 해당 카드를 잠시 강조해 결과를 알아보기 쉽게 한다.

### 인원수 필터

- 필터 선택지는 `전체`, `1인`, `2인`, `3인`, `4인`으로 제공한다.
- 각 선택지에 현재 등록된 포즈 수를 함께 표시한다.
- 인원수를 선택하면 해당 인원수의 포즈만 표시한다.
- 전체를 선택하면 모든 포즈를 다시 표시한다.
- 필터를 바꿀 때 화면 전체를 다시 불러오지 않고 목록 영역을 즉시 갱신한다.
- 포즈 업로드가 완료되면 방금 등록한 인원수 필터를 자동으로 선택해 결과를 바로 보여준다.

### 화면 상태

#### 조회 중

- 포즈 데이터를 불러오는 동안 공통 로딩 상태를 표시한다.
- 로딩 중에는 이전 결과를 빈 목록으로 오해하지 않도록 빈 화면 문구를 표시하지 않는다.

#### 등록된 포즈 없음

- 등록된 포즈가 하나도 없으면 아직 등록된 포즈가 없다는 안내를 표시한다.
- 첫 포즈를 업로드할 수 있는 주요 동작을 함께 제공한다.

#### 필터 결과 없음

- 전체 포즈는 있지만 선택한 인원수의 포즈가 없으면 해당 인원수의 포즈가 없다는 안내를 표시한다.
- 전체 포즈로 돌아갈 수 있는 동작을 제공한다.

#### 조회 실패

- 포즈 목록을 불러오지 못했다는 공통 오류 안내를 표시한다.
- 운영자가 데이터를 다시 불러올 수 있는 동작을 제공한다.

### 반응형 구성

- 넓은 화면에서는 기존 관리자 사이드바와 함께 여러 열의 이미지 카드를 표시한다.
- 사이드바가 사라지는 화면 폭에서는 같은 관리 메뉴를 사용할 수 있는 가로형 모바일 내비게이션을 제공한다.
- 카드 목록은 화면 너비에 따라 4열, 3열, 2열, 1열 순서로 줄어든다.
- 작은 화면에서도 이미지 비율과 카드 내부 정보의 읽기 순서를 유지한다.
- 인원수 필터는 한 줄 가로 스크롤을 허용해 선택지를 지나치게 좁히거나 줄바꿈하지 않는다.
- 모바일에서도 포즈 업로드 버튼을 화면 너비에 맞게 표시한다.

### 포즈 목록 기본 흐름

1. 운영자가 포즈 관리 화면에 진입한다.
2. 시스템이 최근 등록 순서로 전체 포즈를 표시한다.
3. 운영자가 필요한 경우 인원수 필터를 선택한다.
4. 화면이 선택한 인원수에 맞는 포즈와 등록 건수를 표시한다.
5. 운영자가 이미지를 선택하면 크게 보기를 확인한다.
6. 새로운 포즈가 필요하면 포즈 업로드를 선택한다.

## 2. 포즈 업로드

### 화면 설명

하나 이상의 포즈 이미지를 선택하고, 이미지에 공통으로 적용할 인원수를 지정해 등록하는 화면 중앙의 팝업이다. 선택한 이미지는 등록 전에 미리 볼 수 있다.

### 화면 구성

- 업로드 안내
- 함께 찍는 인원수 선택
- 이미지 선택 또는 끌어놓기 영역
- 선택한 이미지 수
- 이미지 미리보기와 개별 제거
- 취소 버튼
- 포즈 등록 버튼

### 이미지 선택

- JPG와 PNG 이미지를 선택할 수 있다.
- 여러 장을 한 번에 선택하거나 파일을 선택 영역에 끌어놓을 수 있다.
- 같은 파일이 중복으로 선택되면 한 번만 목록에 추가한다.
- 지원하지 않는 형식이나 허용 용량을 넘는 이미지는 선택 목록에 추가하지 않고 이유를 안내한다.
- 프로토타입에서는 참고 화면과 동일하게 한 번에 최대 10장까지 선택하며, 장당 10MB를 임시 상한으로 사용한다.
- 실제 운영 환경의 지원 형식, 파일 수와 용량 제한은 이미지 저장 방식과 API 스펙이 확정될 때 최종 결정한다.

### 인원수 선택

- 1인, 2인, 3인, 4인 중 하나를 선택한다.
- 선택한 인원수는 한 번에 등록하는 모든 이미지에 공통으로 적용한다.
- 서로 다른 인원수의 이미지를 등록하려면 인원수별로 나누어 업로드한다.

### 업로드 전 미리보기

- 선택한 이미지를 작은 카드 형태로 표시한다.
- 각 미리보기에서 해당 이미지를 선택 목록에서 제거할 수 있다.
- 선택한 이미지 수와 한 번에 선택할 수 있는 최대 수를 함께 표시한다.
- 이미지가 한 장도 선택되지 않은 경우 등록 버튼을 사용할 수 없게 한다.

### 업로드 처리

- 운영자가 포즈 등록을 선택하면 선택한 이미지와 인원수를 함께 처리한다.
- 처리 중에는 등록 버튼을 다시 누를 수 없도록 하고 진행 상태를 표시한다.
- 한 번의 실행으로 같은 이미지가 중복 등록되지 않도록 한다.
- 업로드 팝업을 취소하면 선택한 파일과 인원수 입력을 초기화한다.

### 업로드 성공

- 등록한 이미지 수를 포함한 성공 안내를 표시한다.
- 업로드 팝업을 닫고 포즈 목록을 갱신한다.
- 방금 등록한 인원수 필터를 선택한다.
- 새로 등록한 포즈를 목록 앞쪽에서 강조한다.

### 업로드 실패

- 업로드 팝업을 열린 상태로 유지한다.
- 운영자가 선택한 이미지와 인원수는 그대로 유지한다.
- 업로드에 실패했다는 안내를 표시한다.
- 일부 이미지만 성공했을 때의 처리와 재시도 방식은 실제 API의 일괄 처리 정책이 확정된 뒤 결정한다.

### 포즈 업로드 기본 흐름

1. 운영자가 포즈 목록에서 포즈 업로드를 선택한다.
2. 함께 찍는 인원수를 선택한다.
3. 한 장 이상의 이미지를 선택하거나 끌어놓는다.
4. 시스템이 형식, 용량, 최대 선택 수와 중복 여부를 확인한다.
5. 운영자가 미리보기를 확인하고 필요 없는 이미지를 제거한다.
6. 운영자가 포즈 등록을 선택한다.
7. 시스템이 업로드를 처리하고 포즈 목록을 갱신한다.
8. 방금 등록한 인원수의 목록과 성공 안내를 표시한다.

## 3. 프로토타입 데이터와 API 연동 경계

### 현재 프로토타입

- 포즈 목록은 화면 확인을 위한 시드 목 데이터로 제공한다.
- 업로드한 이미지는 브라우저 메모리에서만 관리한다.
- 페이지를 새로고침하면 새로 업로드한 데이터는 초기 시드 상태로 돌아간다.
- 조회와 업로드 동작은 공통 관리자 adapter 계약을 통과하며 외부 API를 호출하지 않는다.
- 로딩 시간을 흉내 낸 비동기 처리로 로딩, 성공과 실패 UI를 검증할 수 있게 한다.

### 실제 API 연결 시 필요한 동작

- 포즈 목록과 각 포즈의 이미지, 인원수, 등록 시점을 조회한다.
- 선택한 인원수 조건에 맞는 목록을 조회하거나 전체 조회 결과에서 필터링한다.
- 선택한 이미지 파일과 인원수를 업로드한다.
- 업로드 결과로 등록된 포즈 정보를 반환해 목록을 갱신한다.
- 조회·업로드 실패 사유를 화면에서 사용자 친화적인 안내로 변환한다.

실제 연결에서는 현재 화면 코드를 직접 API 응답 구조에 맞추지 않는다. 별도의 API adapter가 서버 응답을 화면 모델로 변환하고, 현재 목 adapter와 동일한 화면 계약을 구현한다. 페이지네이션, 파일 저장소, 이미지 변환, 중복 판정, 부분 성공과 재시도 정책은 API 스펙이 준비된 뒤 이 경계 안에서 확정한다.

## 4. 완료 기준

- 관리자 메뉴와 모바일 내비게이션에서 포즈 관리 화면에 진입할 수 있다.
- 포즈 목록을 이미지 카드로 확인할 수 있다.
- 전체와 1~4인 필터별 등록 건수와 결과가 일치한다.
- 이미지 파일을 여러 장 선택하고 미리보기와 개별 제거를 사용할 수 있다.
- 인원수를 지정해 목 업로드를 완료하면 목록과 건수가 즉시 갱신된다.
- 조회 중, 데이터 없음, 필터 결과 없음, 조회 실패와 업로드 성공·실패 상태가 구분된다.
- 데스크톱, 태블릿과 모바일 화면에서 문서 전체의 가로 넘침 없이 주요 작업을 수행할 수 있다.
- 실제 API 필드명이나 내부 상태 값을 화면 코드에서 먼저 확정하지 않는다.
