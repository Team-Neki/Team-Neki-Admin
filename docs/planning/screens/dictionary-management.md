# 사전 관리 화면 기획서

## 기능 개요

검색어의 오타·띄어쓰기·자주 쓰는 별칭을 대표 원 단어로 연결하는 검색 정규화 사전이다. 예를 들어 `인샹네컷`을 허용 단어로 등록하면 브랜드 검색에서 `인생네컷`으로 매칭한다.

- 진입 메뉴: 운영 > 사전 관리
- 화면 범위: 사전 목록 조회, 사전 항목 추가·수정
- 현재 동작: 목 adapter 메모리에 저장
- 실제 API 연동 시점: `AdminAdapter.saveDictionary` 계약에 맞춰 연결

사전 관리 메뉴는 이후 사전 유형을 늘릴 수 있는 확장 지점으로 둔다. 현재 프로토타입에서는 브랜드명 별칭 유형만 제공하고, 자치구·지하철역 등 다른 유형은 실제 데이터 계약이 정해진 뒤 별도 탭으로 추가한다.

## 용어

| 용어 | 설명 |
| --- | --- |
| 원 단어 | 검색 결과로 최종 연결할 대표 단어 |
| 허용 단어 | 원 단어로 매칭할 수 있는 오타·띄어쓰기·별칭 목록 |

## 사전 유형 탭 확장

- 현재 탭: `브랜드명 별칭`
- 확장 예정 탭: `자치구`, `지하철역` 등 서비스 검색에 필요한 기준어
- 유형별 데이터 구조와 API 필드는 실제 스펙이 확정될 때 결정한다.

## 목록 화면

- 원 단어 또는 허용 단어로 검색할 수 있다.
- 원 단어, 허용 단어 목록, 허용 단어 수, 최근 수정일을 표시한다.
- 한 페이지에 최대 30개 항목을 표시한다.
- 허용 단어가 검색되면 해당 원 단어 항목을 결과로 표시한다.

## 추가·수정

- 원 단어는 필수 입력이다.
- 허용 단어는 한 줄에 하나씩 입력한다.
- 저장 시 공백 항목과 원 단어와 동일한 허용 단어는 제거한다.
- 같은 원 단어가 이미 있으면 저장하지 않고 중복 안내를 표시한다.
- 저장 성공 후 목록에 즉시 반영하고 변경 항목을 잠시 강조한다.
- 저장 실패 시 입력값을 유지한다.

## 검색 매칭 규칙

- 검색어와 원 단어·허용 단어는 앞뒤 공백을 제거하고 연속 공백을 하나로 무시한 뒤 비교한다.
- 현재 프로토타입은 브랜드 관리의 브랜드명 검색에 사전을 적용한다.
- 사전은 검색어 표시값을 바꾸지 않고, 결과를 대표 원 단어 기준으로 보여준다.

## API 경계

화면은 `DictionaryRecord`와 `DictionaryDraft`만 사용한다. 서버가 준비되면 adapter에서 실제 필드명과 저장 방식을 변환하며, 화면에 API 필드명이나 내부 enum을 노출하지 않는다.
