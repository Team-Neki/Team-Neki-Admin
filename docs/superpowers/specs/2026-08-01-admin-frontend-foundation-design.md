# Neki Admin 프론트엔드 기반 설계

## 1. 목표와 범위

Neki Admin은 별도로 제공되는 백엔드 API를 사용하는 프론트엔드 전용 관리자 애플리케이션이다. 이 문서는 화면별 기능을 정의하지 않고, 이후 관리자 기능을 일관되게 구현하기 위한 기술 스택과 애플리케이션 기반 구조를 결정한다.

초기 애플리케이션은 검색 엔진 노출이나 서버 사이드 렌더링이 필요 없는 SPA로 구성한다. 지원 대상은 Ant Design이 공식 지원하는 최신 데스크톱 브라우저이며, 모바일은 핵심 운영 시나리오가 아닌 보조적인 반응형 접근만 제공한다.

## 2. 기술 스택

| 영역 | 선택 | 역할 |
| --- | --- | --- |
| 언어 및 UI 런타임 | React, TypeScript | 컴포넌트 기반 UI와 정적 타입 검사 |
| 빌드 도구 | Vite | 개발 서버, 번들링, 환경 변수 처리 |
| 패키지 관리 | pnpm | 의존성 및 잠금 파일 관리 |
| 디자인 시스템 | Ant Design | 레이아웃, 폼, 테이블, 모달, 피드백 컴포넌트 |
| 아이콘 | `@ant-design/icons` | Ant Design과 일관된 아이콘 제공 |
| 라우팅 | TanStack Router | 타입 안전한 경로, 파라미터, 검색 조건 관리 |
| 서버 상태 | TanStack Query | API 캐시, 로딩·오류 상태, 재조회, mutation 관리 |
| HTTP 클라이언트 | Axios | 공통 base URL, 헤더, 인증 및 오류 인터셉터 제공 |
| 스키마 검증 | Zod | 외부 데이터와 복잡한 도메인 입력의 런타임 검증 |
| 클라이언트 상태 | Zustand | 서버 상태가 아닌 전역 UI 상태가 실제로 필요할 때만 사용 |
| 차트 | Ant Design Charts | 관리자 지표 시각화 |
| 단위·통합 테스트 | Vitest, React Testing Library, MSW | 로직, UI 동작, API 연동 경계 검증 |
| E2E 테스트 | Playwright | 주요 관리자 작업 흐름을 실제 브라우저에서 검증 |
| 코드 품질 | ESLint, Prettier | 정적 검사와 일관된 포맷팅 |
| 지속적 통합 | GitHub Actions | 타입 검사, 린트, 테스트, 프로덕션 빌드 검증 |

의존성은 프로젝트를 생성하는 시점의 최신 안정 버전을 사용하고 `pnpm-lock.yaml`로 고정한다. 메이저 버전 업그레이드는 별도의 검증 작업으로 처리한다.

## 3. 선택 근거와 제외 사항

프론트엔드 전용 관리자 SPA이므로 Next.js의 서버 렌더링과 서버 컴포넌트는 필요하지 않다. Vite를 사용해 배포 산출물을 정적 파일로 단순화한다.

Ant Design을 단일 주력 디자인 시스템으로 사용한다. shadcn/ui를 함께 사용하면 폼, 모달, 테이블, 테마 체계가 중복되므로 제외한다. Tailwind CSS도 초기 기반에서는 제외하고 Ant Design Theme Token과 CSS Modules로 보완한다. Ant Design으로 표현하기 어려운 요구가 실제로 생길 때에만 추가 도입을 검토한다.

폼은 Ant Design Form으로 통일하며 React Hook Form을 중복 도입하지 않는다. 표는 Ant Design Table을 사용하며 TanStack Table을 추가하지 않는다. Zod는 모든 단순 폼 규칙을 재작성하는 용도가 아니라 API 응답 및 여러 화면에서 공유하는 도메인 규칙을 검증하는 데 사용한다.

Zustand는 기본 의존성 후보지만 초기부터 모든 상태를 저장하지 않는다. API에서 온 데이터는 TanStack Query, URL에 남아야 하는 필터와 페이지 정보는 TanStack Router, 단일 컴포넌트 상태는 React가 각각 소유한다. 이 셋으로 표현할 수 없는 전역 UI 상태에만 Zustand를 사용한다.

## 4. 애플리케이션 구조

코드는 역할과 기능 경계를 함께 드러내도록 구성한다.

```text
src/
  app/          # 애플리케이션 초기화, 전역 Provider, 라우터 설정
  routes/       # URL과 페이지 진입점
  features/     # 회원, 콘텐츠, 신고 등 업무 기능 단위
  components/   # 여러 기능에서 공유하는 제품 컴포넌트
  api/          # Axios 인스턴스, API 계약, 공통 오류 변환
  schemas/      # 공유 Zod 스키마
  styles/       # 전역 스타일과 Ant Design 테마 토큰
  test/         # 테스트 초기화와 공통 MSW 구성
```

각 `features` 모듈은 해당 업무의 API 함수, 쿼리 옵션, 화면 컴포넌트, 테스트를 가까이 둔다. 범용성이 확인되지 않은 코드는 성급하게 공용 디렉터리로 이동하지 않는다. `routes`는 조합과 접근 제어를 담당하고 업무 로직을 직접 구현하지 않는다.

## 5. 데이터 흐름

1. TanStack Router가 URL 경로와 검색 조건을 검증한다.
2. 라우트 또는 기능 컴포넌트가 TanStack Query의 query/mutation을 호출한다.
3. query/mutation은 `api` 계층의 Axios 클라이언트를 통해 백엔드와 통신한다.
4. 외부 데이터 검증이 필요한 응답은 Zod 스키마를 통과시킨다.
5. 성공한 서버 데이터는 TanStack Query 캐시에 저장하고 Ant Design 컴포넌트에 표시한다.
6. 변경 작업이 성공하면 관련 쿼리를 무효화하거나 캐시를 명시적으로 갱신한다.

목록의 페이지, 정렬, 검색, 필터 값은 가능한 한 URL 검색 조건에 둔다. 새로고침과 링크 공유 후에도 같은 조회 상태를 복원할 수 있어야 한다.

## 6. 인증과 접근 제어 경계

인증 방식은 백엔드가 제공하는 계약을 따르되, 화면 코드에 직접 결합하지 않는다. Axios 요청 인터셉터는 인증 정보를 요청에 적용하고, 응답 인터셉터는 인증 만료와 표준 오류를 공통 애플리케이션 오류로 변환한다.

라우트 접근 제어는 인증 상태와 관리자 권한을 확인한 뒤 허용되지 않은 진입을 로그인 또는 권한 안내 화면으로 보낸다. 프론트엔드의 접근 제어는 사용자 경험을 위한 것이며, 실제 권한 검증은 백엔드가 최종 책임을 가진다는 전제를 유지한다.

## 7. 오류 및 사용자 피드백

API 오류는 네트워크 오류, 인증 만료, 권한 부족, 검증 오류, 서버 오류로 정규화한다. 각 화면은 로딩, 빈 결과, 부분 실패, 전체 실패 상태를 구분한다.

사용자가 다시 시도할 수 있는 조회 실패에는 재시도 동작을 제공한다. 생성·수정·삭제 결과는 Ant Design의 message 또는 notification으로 알리되, 필드 검증 오류는 해당 Form 항목 가까이에 표시한다. 파괴적인 변경은 확인 Modal을 거친다.

예상하지 못한 렌더링 오류는 최상위 오류 경계에서 처리하여 빈 화면을 방지하고, 개발 환경에서는 원인 추적에 필요한 상세 정보를 노출한다.

## 8. 스타일과 테마

Ant Design `ConfigProvider`를 애플리케이션 루트에 두고 브랜드 색상, 글꼴, 모서리, 간격 관련 Theme Token을 한곳에서 관리한다. 컴포넌트 내부 구현을 선택자로 강하게 덮어쓰지 않는다.

페이지 고유 레이아웃은 CSS Modules로 작성한다. 전역 CSS는 리셋, 문서 기본값, 공통 토큰 연결처럼 애플리케이션 전체에 필요한 규칙으로 제한한다.

## 9. 테스트 전략

- 순수 유틸리티와 스키마는 Vitest로 검증한다.
- 컴포넌트의 사용자 동작은 React Testing Library로 검증한다.
- API 의존 화면은 MSW로 성공, 빈 결과, 지연, 오류 응답을 재현한다.
- Playwright는 로그인, 주요 목록 조회, 필터링, 생성·수정 같은 핵심 운영 흐름만 선별해 검증한다.
- GitHub Actions는 모든 변경에서 타입 검사, ESLint, 단위·통합 테스트, 프로덕션 빌드를 실행한다.

테스트는 내부 구현이나 CSS 클래스보다 사용자가 보는 역할, 이름, 결과를 기준으로 작성한다.

## 10. 완료 기준

이 기반 설계의 구현은 다음 조건을 모두 만족할 때 완료된다.

- 로컬 개발과 프로덕션 빌드 명령이 pnpm으로 재현된다.
- 타입 안전한 기본 라우트와 404 화면이 동작한다.
- Ant Design 전역 테마와 기본 관리자 레이아웃을 적용할 수 있다.
- TanStack Query와 Axios의 API 연동 경계가 마련된다.
- 공통 로딩 및 오류 처리 방식이 예제 화면에서 검증된다.
- Vitest, MSW, Playwright 테스트 기반과 GitHub Actions 검증이 동작한다.
- README에 설치, 환경 변수, 실행, 테스트, 빌드 방법이 기록된다.
